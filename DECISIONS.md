# DECISIONS.md

Choices made where the spec was silent or ambiguous. Format: date, question, choice, reason.

## 2026-11-10 (M0)

1. **Query prefix for the embedder.** Choice: `EMBED_QUERY_PREFIX` defaults to `Represent this sentence for searching relevant passages: `. Reason: this is the query instruction on the `BAAI/bge-small-en-v1.5` model card; the card says v1.5 works without it but recommends it for short queries against longer passages. Passages get no prefix.
2. **Settings not in the section 5 table.** Choice: added `STORE_PREFIX` (default empty; tests use `test_`, prepended to Qdrant collection and OpenSearch index names), `STORE_TIMEOUT_S` (default 5; connect/request timeout for the four store clients and each `/healthz` check) and `EMBED_DIM` (384, from section 4). Reason: AGENTS.md requires the `test_` prefix, a timeout on every network call, and no size or timeout constants outside `config.py`.
3. **Re-runnable migrations instead of a tracking table.** Choice: `001_init.sql` is the section 6.2 schema with `IF NOT EXISTS` on every `CREATE`; `make migrate` runs every file in `migrations/` in name order, each in a transaction. Later migrations must also be re-runnable. Reason: a `schema_migrations` table would add a table the spec does not list.
4. **`make migrate` also creates the Qdrant collections and the OpenSearch index.** Choice: after the SQL, it creates `chunks_{INDEX_VERSION}` and `answer_cache_{INDEX_VERSION}` (384-dim cosine, keyword payload indexes from section 6.3) and the OpenSearch index with the section 6.4 mapping, if missing. Reason: one command prepares every store schema; the worker and API can assume they exist.
5. **`opensearch-py[async]`.** Choice: install the `async` extra, which pulls in `aiohttp`. Reason: `AsyncOpenSearch` needs it, and AGENTS.md requires async I/O in the API service.
6. **Selector event loop on Windows.** Choice: `asyncio.run(..., loop_factory=asyncio.SelectorEventLoop)` in the scripts, `uvicorn --loop asyncio:SelectorEventLoop` in `make api`, and a `pytest_asyncio_loop_factories` hook in `tests/conftest.py`. Reason: psycopg's async mode cannot run on the Windows default proactor loop; the selector loop works on every platform.
7. **Two modules not in the section 3 layout.** Choice: `rag/common/migrate.py` (entry point of `make migrate`) and `rag/common/seed.py` (the section 12 users, tuples and keys, entry point of `make seed`). Their SQL lives in `pg.py`. Reason: the layout names no home for these commands.
8. **Trailing whitespace in `normalize_query`.** Choice: after stripping trailing `?`, `!` and `.`, strip whitespace again, so `"who approves ?"` and `"who approves"` normalize the same. Reason: the spec's order would otherwise leave a trailing space.
9. **User text that `FakeLLM` parses for `rewrite`.** Choice: the rewrite prompt's user text lists turns as lines `user: ...` / `assistant: ...` and ends with `question: ...`; the fake returns the last `user:` line and the question joined by a space. Reason: section 4 defines the fake's output but not the prompt layout; `prompts/rewrite_v1.txt` (M6) must use this layout.
10. **Dependencies are added with the milestone that uses them.** Choice: M0 installs only what its code imports; `sentence-transformers` and `watchfiles` come with the code that uses them. Reason: minimal code; no unused dependencies.
11. **Pinned images.** Choice: `postgres:18.6`, `redis:8.10.3`, `qdrant/qdrant:v1.20.0`, `opensearchproject/opensearch:3.9.0` (the newest non-rc releases on Docker Hub on this date). Postgres 18 images declare their volume at `/var/lib/postgresql` (not `.../data`), so the named volume is mounted there. Integration tests use the Postgres database `test_rag`.
12. **Store addresses use `127.0.0.1`, and Redis is published on host port 6380.** Choice: the default `PG_DSN`, `REDIS_URL`, `QDRANT_URL` and `OPENSEARCH_URL` use `127.0.0.1`; Compose maps Redis to `6380:6379`. Reason: on this laptop `localhost` resolves to `::1` first and IPv6 connections to the published ports hang until timeout, and host port 6379 is already taken by a separate Valkey server (version 7.2.4) outside this project, so clients on 6379 silently reached the wrong server.

## 2026-11-10 (M1)

13. **Token counting for chunk sizes.** Choice: the `Embedder` interface gains `count_tokens(text)`. The real embedder counts the model tokenizer's ids without special tokens; `FakeEmbedder` counts the `tokens()` words, so tests never download the tokenizer. Reason: section 5 says sizes are counted with the embedding model's tokenizer, and the chunker must stay pure, so it takes the counter as an argument.
14. **Two worker settings.** Choice: `RECLAIM_IDLE_MS` (default 30000, the spec's 30 seconds; also the reclaim loop's interval) and `WORKER_BLOCK_MS` (default 2000, how long one `XREADGROUP` waits; kept below `STORE_TIMEOUT_S` so the Redis socket timeout never fires first). Reason: no timeouts as constants outside `config.py`, and tests need to reclaim without waiting 30 seconds.
15. **When a job is dead-lettered.** Choice: after a failed attempt, the worker reads the delivery count from `XPENDING`; if it is at least `MAX_DELIVERIES`, it copies the job to `ingest:dead` (with `error` and `deliveries`) and acknowledges it in one transaction. A job is therefore tried exactly `MAX_DELIVERIES` times. Reason: this matches the TASKS.md test wording ("after `MAX_DELIVERIES` attempts") and keeps the error text of the last attempt.
16. **Name of the `hash` step.** Choice: the function is `hash_file`. Reason: `hash` would shadow the builtin.
17. **A deleted document whose file comes back unchanged is re-ingested.** Choice: the hash check skips a file only when the hashes match and `deleted_at` is NULL. Reason: otherwise restoring a deleted file with the same bytes would never make it searchable again.
18. **`index_new` first removes leftovers at its own version.** Choice: before upserting version `v`, delete the document's chunks with `version >= v` from Qdrant and OpenSearch. Reason: a job that failed between `index_new` and `commit` leaves chunks at version `v`; a retry with different content (fewer chunks) would otherwise leave stale chunks with a valid version.
19. **Folders.** Choice: `documents.folder` holds the folder path without the `folder:` prefix (`specs`, `a/b`, `_root` for files directly under `CORPUS_DIR`). Top-level folders get no `parent` tuple. A delete job removes only the document's own `parent` tuple, because folder tuples may be shared. Reason: section 7 gives no parent above a top-level folder.
20. **Stamping in M1.** Choice: `stamp` already computes `principals = document_readers(doc_id)` with the section 7.1 query, in `rag/common/permissions.py`. The SQL lives in `pg.py`. The M2 checkbox for stamping stays open until M2's permission tests cover it. Reason: the query is fixed by the spec and needed for indexing; leaving `principals` empty would only be replaced in the next milestone.
21. **Smaller worker details.** Choice: in `events:changes`, `doc_ids` is a JSON list encoded as a string (stream fields are flat strings). The worker runs one job at a time (one lock shared by the consumer and reclaim loops). OpenSearch writes and deletes use `refresh`, so new chunks are searchable at once and `delete_by_query` sees every chunk. An `upsert` job for a file that no longer exists is acknowledged and skipped, because the matching `delete` job follows. Reason: the simplest choices that keep writes idempotent and readers consistent.
22. **Chunk boundaries.** Choice: sections are contiguous slices of the file (the heading line included in the section text; a blank preamble is dropped), parents are slices of sections, and children are slices of parents, so children concatenate exactly to their parent. Sentence boundaries are `.`, `!` or `?` followed by whitespace, or a line break; a sentence larger than `CHILD_TOKENS` falls back to word boundaries. A parent's `heading` is the heading of its first section. `.txt` files are one section with no heading. Reason: section 9.2 fixes the units but not these details.

## 2026-11-10 (M2)

23. **Where the reranker gets chunk text.** Choice: `rerank` reads the candidates' child texts from OpenSearch by `chunk_id` (one `mget`), because the section 6.3 Qdrant payload has no text and dense-only candidates would otherwise have none. A failure or timeout of that read counts as a reranker failure (fused order, `rerank` in `degraded`). A chunk missing from the read (removed by a re-index since retrieval) is scored on empty text; `hydrate` drops it when its parent is gone. Reason: keeps the Qdrant payload exactly as specified.
24. **Fallback order when reranking fails.** Choice: keep the first `RERANK_KEEP` candidates of the fused order with their RRF scores, which `hydrate` then uses to keep each parent's best score. Reason: section 8 step 11 says "keep the fused order"; `RERANK_KEEP` still bounds the context.
25. **The temporary `POST /search`.** Choice: body `{"question"}`, header `X-API-Key`, response `{"request_id", "parents": [{parent_id, doc_id, version, path, heading, text, score}], "degraded"}`; both branches failing returns 503 `{"code": "retrieval_unavailable"}`. It runs steps 1, 2, 6 and 8 to 12 and is removed in M3. Reason: TASKS.md asks for it but fixes no shape.
26. **A missing `X-API-Key` header** is treated like an unknown key: 401 `unauthorized`. Reason: default deny.
27. **Real reranker returns raw logits.** Choice: the cross-encoder is loaded with `activation_fn=torch.nn.Identity()`. Reason: section 4 says scores are raw logits, and sentence-transformers otherwise picks the activation from the model's config.
28. **Location of the default-deny test.** Choice: `tests/integration/test_default_deny.py`, as TASKS.md names it, not `tests/test_default_deny.py` as AGENTS.md says. Reason: it searches the real stores, so it belongs with the integration tests.
29. **Forcing a branch timeout before M7.** Choice: `test_retrieve.py` replaces the `dense` or `sparse` function with one that sleeps past `RETRIEVE_TIMEOUT_MS`; the real `asyncio.wait_for` in `retrieve` produces the timeout. The fault wrappers of section 11 arrive in M7. Reason: M2 has no fault-injection code yet.
30. **Shared fixture facts for tests.** Choice: the code words and the per-key readable sets of section 12 live in `tests/fixture_corpus.py`, importable because `pythonpath = ["tests"]` is set for pytest. Reason: three test modules need them.

## 2026-11-10 (M3)

31. **LLM failure in `generate`.** Choice: `LLM_TIMEOUT_S` bounds the whole stream. "Before any token is sent" is read as "before the LLM yielded any text": then the extractive fallback (section 8.3) is the answer. A failure after some text arrived keeps the partial answer. In both cases `llm` is added to `degraded`. The fallback is built in M3 because step 14 needs it; its fault tests arrive in M7. It skips Markdown heading lines when taking a parent's first two sentences. Reason: the output guard buffers, so "sent to the client" is not a clear point; this is the simplest reading.
32. **`ANSWER_MAX_TOKENS`** (default 1024) is the `max_tokens` of the answer call. Reason: no size constants outside `config.py`.
33. **Events after the tokens.** Choice: `citations` lists only the blocks the guarded answer cites, by block number; then `warning` (`uncited`) if there are none; then `done`. An abstention sends its fixed text as one `token` event, an empty `citations` and no warning. Reason: section 10 fixes the payloads but not these details.
34. **Context budget.** Choice: each parent's text is counted with `Embedder.count_tokens`; if no parent fits `CONTEXT_TOKEN_BUDGET`, the request abstains. Reason: the same counter as the chunk sizes; an empty context cannot be answered.
35. **Timings in M3.** Choice: `timings` holds the steps M3 runs (`authenticate`, `expand`, `embed`, `retrieve`, `rrf`, `recheck`, `rerank`, `hydrate`, `assemble`, `generate`, `persist`). `generate` covers the interleaved stream and output guard; `persist` is logged in `ask_done` but cannot be in the row it writes. Separate per-step timings for all sixteen steps are M7. Reason: `requests.timings` is `NOT NULL`.
36. **What `persist` stores.** Choice: `cache_tier = 'none'`, `rewritten = NULL` (rewriting arrives in M6), `doc_ids` = the documents in the context (empty for an abstention), `answer` = the guarded text. A request that ends in `retrieval_unavailable` is logged, not persisted. Reason: simplest choices consistent with section 6.2.
37. **Output guard details.** Choice: a released sentence is a `sentences()` piece (the chunker's rule, moved to `rag/common/text.py`); unmatched PII becomes `[redacted]`; a dropped citation marker takes its leading whitespace with it. The email / 13-to-19-digit pattern `PII` lives in `text.py` for reuse by `input_guard` in M6. Reason: one sentence rule for the whole system.
38. **`/search` removed.** Choice: `test_visibility.py` and `test_default_deny.py` call `pipeline.search` (the retrieval half of `/ask`, steps 2, 6, 8 to 12) as the fixture users, because the fake LLM always cites only `[1]`, so `/ask` citations cannot show every visible document. The unknown-key test moved to `test_ask.py`. The integration reset now also truncates `turns` and `requests`. Reason: keeps the M2 assertions at full strength.
39. **LLM adapter and CLI.** Choice: `LLM_BASE_URL` includes the API version path (for example `https://api.openai.com/v1`); the adapter posts to `chat/completions` with a new `httpx.AsyncClient` per call, timeout `LLM_TIMEOUT_S`. The CLI takes `--url` (default `http://127.0.0.1:8000`) and `--session` (default a new UUID), and uses `STORE_TIMEOUT_S` to connect and `LLM_TIMEOUT_S` between stream reads. Reason: no client lifecycle to manage; prompt caching depends only on the byte-identical system text.
40. **Malformed `/ask` bodies** get FastAPI's default 422. Reason: section 10 lists no code for them; mapping them would add an error code the spec does not define.

## 2026-11-10 (M4)

41. **Which documents a tuple change affects.** Choice: for `viewer` the object, for `parent` the subject (the document, or the folder whose contents moved); the invalidator re-stamps every live document at or beneath that node, following `parent` tuples downward in one recursive query. `principals` is overwritten on all of a document's chunks whatever their version. Reason: a `parent` tuple changes the ancestors of its subject, not of its object; following tuples instead of `documents.folder` also covers `parent` tuples added through `/admin/tuples`.
42. **Invalidator runs inside the worker process.** Choice: `make worker` runs the invalidator's consumer and reclaim loops next to the job loops, sharing the job lock, so a re-stamp never interleaves with an ingestion of the same document. A failed event stays pending and is retried by the reclaim loop after `RECLAIM_IDLE_MS`; there is no dead-letter stream for events. `doc_changed` and `doc_deleted` events are acknowledged without action until the M5 purge. The `invalidators` group is created at id `0`, so events written before the worker first started are still handled. Reason: section 9.3 names no failure handling; a lost re-stamp would never be repaired by a TTL, and re-stamping is idempotent.
43. **`/admin/tuples` details.** Choice: the tuple is written in its own transaction and the event is added only after the commit, so the invalidator always reads the new tuples. Every accepted request emits an event, even when the tuple already existed or was absent. A non-admin, unknown or missing key gets 401 `unauthorized`; a malformed body gets FastAPI's 422 (as in decision 40). Reason: simplest choices consistent with section 10.
44. **Stream helpers take the stream and group.** Choice: `redis_.ensure_group`, `read_new`, `claim_idle` and `ack` replace the job-only versions, and the worker's consume and reclaim loops take the step to repeat. Reason: the invalidator needs the same stream operations; this avoids a second copy of each.

## 2026-11-10 (M5)

45. **Namespace of the `answer_cache` point ID.** Choice: `answer_point_id(cache_key)` = UUID5(`NAMESPACE_URL`, `cache_key`), in `rag/common/ids.py`. Reason: section 6.3 says "UUID5 of the cache key" without a namespace; `NAMESPACE_URL` is the one `doc_id` already uses. The cache key itself is exactly section 8 step 5.
46. **How the invalidator finds a document's `chunk:` keys.** Choice: it scans `chunk:*` and deletes the keys whose stored `doc_id` is one of the event's documents (one scan per event, for all its documents). Reason: by the time `doc_changed` arrives, `cleanup` has already deleted the old parents from Postgres, and `parent_id` does not contain the `doc_id`, so no lookup remains; section 6.5 has no key listing a document's parents, and adding one would change the Redis key set. The scan is bounded by the number of cached parents, which is small on a laptop. If the owner prefers a `doc2chunk:{doc_id}` set, that is a new key and needs the owner's approval.
47. **Which `answer_cache` points the purge deletes.** Choice: every point whose `doc_ids` payload contains one of the documents (one filtered delete, using the `doc_ids` payload index of section 6.3), not only the points of the cache keys in `doc2ans:`. Reason: the two sets are the same when the caches are consistent, and the filter also removes a point whose `doc2ans:` set was lost.
48. **When "without delaying the response" writes the caches.** Choice: `ask` writes the caches after it has yielded the `done` event, so the client already has every event; a cache write failure is logged (`cache_write_failed`) and nothing else. A client that disconnects before the stream ends skips the write. Reason: no background task to track, and tests see the writes as soon as the response body ends.
49. **What a cache hit sends.** Choice: the cached answer as one `token` event, the cached `citations`, then `done` with `cache_tier` `exact` or `semantic` and empty `degraded`. The `requests` row stores the tier, the cached `doc_ids` and only the timings of the steps that ran (`authenticate`, `expand`, `exact_cache`, and on a semantic hit `embed` and `semantic_cache`). A semantic hit writes nothing new to the caches. Reason: section 8.4 caches only `cache_tier = none`; the stored answer already passed the output guard.
50. **Entities on the semantic cache.** Choice: only the nearest point (limit 1) with the user's fingerprint is considered; it hits only if its similarity reaches `SEMANTIC_CACHE_THRESHOLD` and its `entities` equal `extract_entities(question)`. A cache read error is not caught. Reason: section 8 step 7 names the nearest point; section 11 lists no Redis or answer-cache fault.
51. **`pipeline.search` takes principals and the query vector.** Choice: `search` is now steps 8 to 12 only; `ask` runs `expand` and `embed` (the latter inside the cache lookup, since step 7 needs the vector). The test helper `search_paths` calls `expand` and `embed` itself. Reason: the vector is computed once per request, before the semantic cache.

## 2026-11-10 (M6)

52. **Steps 1 to 3 run before the stream opens.** Choice: `/ask` runs `authenticate`, `expand` and `input_guard` in the endpoint (the first two on one Postgres connection), then `pipeline.ask` runs steps 4 to 16 as the event stream. `timings` now also holds `input_guard` and `rewrite`. Reason: section 10 requires 400 and 429 errors as plain JSON before the stream opens.
53. **Rate limit details.** Choice: only known keys are counted (the lookup comes first, so an unknown key gets 401 and no counter). The window is the fixed epoch minute of section 6.5; each request runs `INCR` and `EXPIRE` in one transaction, and the request that takes the counter above `RATE_LIMIT_PER_MIN` gets 429 `rate_limited`. Every endpoint that calls `authenticate` (`/ask`, `/feedback`, `/admin/tuples`) counts against the same per-key limit. New setting `RATE_LIMIT_TTL_S` (default 120, the TTL in section 6.5). Reason: section 5 says "requests per API key", and no TTL constant may live outside `config.py`.
54. **Rewrite details.** Choice: the history is the last `HISTORY_TURNS` rows of `turns` (a user turn and an assistant turn count as one each) for this `session_id` and this user, oldest first, each collapsed to one line in the layout of decision 9. Another user's turns under the same `session_id` are never used. The call uses `LLM_SMALL_MODEL`, new setting `REWRITE_MAX_TOKENS` (default 256) and `LLM_TIMEOUT_S`; an empty reply counts as a failure. The rewritten question is the query for steps 5 to 15 (cache key, entities, embedding, retrieval, reranking and the prompt); `turns` and `requests.question` keep the original, and `requests.rewritten` holds the rewrite, or NULL when there was no history or the rewriter failed. A cache hit after a failed rewrite still reports `rewrite` in `degraded`. Reason: section 8 step 6 embeds "the rewritten question"; reading history across users would leak one user's questions to another.
55. **`input_guard` details.** Choice: it checks the original question, in the order `too_long` (Python string length over `MAX_QUESTION_CHARS`), `injection` (the section 8.1 patterns, kept as `INJECTION` in `rag/common/text.py`), `pii` (the `PII` pattern the output guard uses); the first match wins. Reason: simplest reading of step 3.
56. **`/feedback` details.** Choice: the key is authenticated (and rate-limited) as for `/ask`; feedback is stored only for one of the caller's own requests, and any other `request_id` gets 404 `{"code": "not_found", "message": "unknown request_id"}`. A malformed body or a rating other than 1 or -1 gets FastAPI's 422 (decision 40). Each accepted post inserts one row, so repeating it stores the rating twice: `feedback` has no key, and making the write idempotent needs a unique constraint on `request_id`, which changes a table. **Owner question:** add `UNIQUE (request_id)` (and upsert) to `feedback`? Reason: section 10 names no error code for 404; a user must not rate other users' requests.

## 2026-11-10 (M7)

57. **Where the fault wrappers sit.** Choice: `faults.inject(redis, component, FAULT_SLOW_MS)` is the first call inside `dense`, `sparse` and the reranker's scoring (so the branch and reranker timeouts cover the injected delay), and `FaultyLLM` wraps the LLM in `pipeline.open_deps`, so every LLM call (answer, rewrite, judge) applies the `llm` fault. `fault:{component}` is read on every call; an unknown value counts as no fault. `test_retrieve.py` and the degraded-answer test in `test_cache.py` now force their failures through `fault:` keys instead of replacing functions (replaces decision 29). `POST /admin/faults` authenticates like `/admin/tuples` (admin key, else 401; counts against the rate limit). Reason: section 11 asks for wrappers in the production path; the timeouts of section 8 must turn `slow` into a failure.
58. **`slow` LLM with the default settings.** Choice: defaults are unchanged, so `FAULT_SLOW_MS` (5 s) is below `LLM_TIMEOUT_S` (30 s) and a `slow` LLM only delays the answer; the fault tests lower `LLM_TIMEOUT_S` and `RERANK_TIMEOUT_MS` so that `slow` outlasts every timeout, as section 11's table expects. **Owner question:** raise `FAULT_SLOW_MS` above `LLM_TIMEOUT_S` (or lower the LLM timeout) so `slow` gives the extractive fallback out of the box? Reason: the spec's defaults and its fault table disagree; changing a default would change the spec.
59. **Timings of `generate`, `output_guard` and `persist`.** Choice: `generate` is the time spent waiting for the LLM's pieces; `output_guard` is the time spent waiting for the guard's released sentences minus that LLM time, plus building the closing events. `persist` is the duration of the turns-and-request transaction, written into the row's `timings` by an `UPDATE` right after the commit. Cache writes after `done` are not timed. A cache hit's row holds only the steps that ran (`authenticate`, `expand`, `input_guard`, `rewrite`, `exact_cache`, `persist`, plus `embed` and `semantic_cache` on a semantic hit); an abstention has no `generate` or `output_guard`. Reason: the stream and the guard interleave, and a row cannot hold the duration of its own insert.
60. **How `score.py` calls the pipeline.** Choice: for each golden question it runs `expand`, `embed`, `search` (steps 8 to 12) and `answer` (steps 13 to 15) as the named user, skipping the cache steps and `persist`, so an evaluation writes no turns, requests or caches. The ranked list is the documents of the hydrated parents in score order (at most `RERANK_KEEP` children, so recall@10 is over the reranked top 10 with the default). Faithfulness judges every sentence of each non-abstained answer against the assembled context with `prompts/judge_v1.txt` (user text: the context blocks and question, then `Sentence: ...`); a reply starting with `1` counts as supported. Percentiles are nearest-rank. `eval_runs.config` is the settings without the store addresses and `LLM_API_KEY`. New setting `JUDGE_MAX_TOKENS` (default 4). `pipeline.Outcome` gains `context` so the judge sees the exact context. `pipeline.open_deps` / `close_deps` are shared by the API and `score.py`. `make eval` uses the environment's stores and models. Reason: section 13 says "caches bypassed" without fixing the mechanism; persisting evaluation questions would mix them into the request log.
61. **Extractive fallback check.** Choice: kept as built in M3 (decision 31): the top three context parents by score, each its first two non-heading sentences and its `[n]` marker, one line each. It matches section 8.3; `test_faults.py` now covers it under `llm` down and slow. Reason: no change needed.

## 2026-11-10 (M8)

62. **PDF parser: `docling`.** Choice: `docling` (2.150, MIT licence), the spec's first choice. It installs on Windows with Python 3.12 and adds about 300 MB to the environment (torch is already there for sentence-transformers). Its layout and table models (about 500 MB) download from Hugging Face the first time a PDF is parsed; afterwards a one-page PDF converts in about 2 seconds plus about 10 seconds to load the models once per process. `pymupdf4llm` was tried on the same fixture and also gives a correct table, but it is AGPL-licensed and was not needed. Reason: section 2 names docling first, and it is heavy but practical on this laptop.
63. **How a PDF becomes sections.** Choice: `parse` converts a `.pdf` with docling (OCR off, table structure on) to Markdown and splits that with the existing Markdown splitter, so headings start sections and tables stay whole; a PDF section's text is docling's Markdown, not the file bytes. The converter is built lazily once per process (`functools.cache`), and the worker runs `parse` in a thread so a slow conversion does not block the invalidator. Scanned PDFs without a text layer yield no text. Reason: one splitting rule for all formats; OCR would add more model downloads and the spec does not ask for it.
64. **Fixture PDF.** Choice: `tests/fixtures/make_pdf.py` writes `tests/fixtures/pdf/price-list.pdf` with the standard library only (Helvetica, one 20-point heading, one paragraph, one ruled 3-by-3 table holding the code word `QUARTZ-5`), byte-identical on every run. It is kept outside `tests/fixtures/corpus/` so the twelve-document fixture corpus and its counts stay as section 12 defines them; `test_pdf.py` copies it to `public/price-list.pdf`. Reason: a reproducible fixture with no new dependency.
65. **`contextualize` details.** Choice: the document is the concatenated section texts, cut to its first `CONTEXT_DOC_TOKENS` (default 2000) tokens with `Embedder.count_tokens` at word boundaries; one small-LLM call per parent, run concurrently, with `CONTEXT_MAX_TOKENS` (default 128) and `LLM_TIMEOUT_S`; the reply is cut to its first two sentences on one line. User text: `<document>` block, then `<chunk>` block. An empty reply or an LLM failure fails the job, so it is retried and dead-lettered like any other failure; there is no fallback to uncontextualized chunks, because a document would then be indexed inconsistently. The worker's LLM goes through the same `llm` fault wrapper as the API's. The indexed child text (embedded in Qdrant, stored in OpenSearch and read by the reranker) is `context + "\n" + child`, so it may exceed `CHILD_TOKENS` by the context's length; `parents.text` stays the original and `parents.context` holds the context. Reason: section 9.2 step 4 fixes the call and the text layout, not these details.
66. **Turning contextual chunking on or off does not re-index by itself.** Choice: the hash check still skips unchanged files, so the owner changes `INDEX_VERSION` (and runs `make migrate`) when flipping `CONTEXTUAL_CHUNKING`, as for any chunking change (section 5). Reason: the setting is part of how chunks are built, which is what `INDEX_VERSION` versions.
67. **Running the integration suite with contextual chunking on.** Choice: `make test-int-context` runs `pytest -m integration` with `CONTEXTUAL_CHUNKING=true` exported (a target-specific make variable, so it works from Git Bash, Linux and macOS); the test settings read it from the environment. `test_context.py` sets the value it tests explicitly, so it covers both modes in either run. Reason: TASKS.md asks that all earlier tests pass with contextual chunking on; a second target keeps `make test-int` as specified.
68. **Containers.** Choice: one `Dockerfile` (base `python:3.12.16-slim-trixie`, `uv` 0.9.13 copied from its image, `uv sync --locked --no-dev`) builds the image `rag-laptop:0.1.0` used by both the `api` and `worker` services, which differ only in their command. Both are in the Compose profile `app`, read `.env` if present, and get store addresses by service name (`postgres:5432`, `redis:6379`, `qdrant:6333`, `opensearch:9200`) that override `.env`. The worker bind-mounts `./corpus` and sets `WATCHFILES_FORCE_POLLING=true` (a `watchfiles` variable, not a project setting), because file events from a Windows or macOS host folder do not reliably reach a container. Models are cached in a `model-cache` volume. Migrations and seeding stay host commands. Reason: the two services share every dependency, so two Dockerfiles would be duplicates.
69. **CPU-only torch on Linux.** Choice: `torch` and `torchvision` are listed as direct dependencies only so that `[tool.uv.sources]` can take them from the PyTorch CPU index on Linux; Windows and macOS keep the PyPI wheels. Reason: the PyPI Linux wheels pull in about 3 GB of CUDA libraries that a laptop container never uses. They were already installed (sentence-transformers needs torch, docling needs torchvision), so no new package is added.
